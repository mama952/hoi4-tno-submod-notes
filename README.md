# 钢铁雄心 IV 子 mod 开发踩坑集（TNO / 大型 overhaul 向）

> 一个中型子 mod（1300+ 国策、500+ 事件、地图级新增国家）从零到能跑通，踩过的 **31 个坑**。
> 每条都写清「症状 → 原因 → 正确写法」，全部经过实机验证（`error.log` 零错误为准）。
>
> 适用环境：HOI4 1.19.x + The New Order（TNO）1.10.x + 中文汉化 + Linux/Windows 混合工具链。

---

## 为什么会有这份文档

HOI4 的脚本引擎有几个特点，让报错信息极具误导性：

- **错误行号经常指向前一行或后一行**，甚至指向文件头
- **大部分结构性错误不报错，只是静默失效**（比如整个决议分类下的条目全都不生效）
- **同一个词法错误在不同上下文里报不同的错**（修饰符当效果用，报的是 `Unknown effect-type`）
- **地图文件的格式要求非常死**，但引擎只会说一句「load 失败」或干脆不说

所以下面这些坑，基本都是「代码看起来完全正常，但游戏就是不对」的类型。

## 十条最贵的

如果只看十条，看这十条（每条的细节在对应文件里）：

1. **事件 id 必须是「本文件已声明的命名空间.编号」，且只能有一个点** —— `W_GER_1` 不行、`SXLG.W_GER.1` 也不行
2. **`ideas` 文件必须有 `ideas = { country = { … } }` 外层** —— 少了这层，整份文件里 200 多个理念全部消失
3. **修饰符（`xxx_factor`）不能当效果直接写** —— 引擎只认 `add_stability` 这类，其余要包成限时理念
4. **决议分类必须放 `common/decisions/categories/`** —— 写在 decisions 文件里会 `Unknown category`，**该分类下所有决议静默失效**
5. **本地化里的 `\n` 必须是字面反斜杠 n** —— Python 普通字符串会写成真换行，导致整行文本丢失
6. **`definition.csv` 的 RGB 三列就是位图里的实际颜色**，不是按省份编号算出来的
7. **`terrain.bmp` 必须保持索引（P）模式** —— 存成 RGB 会变大三倍且引擎可能读错
8. **国策树的 `country` 块带 `add = N` 会被开局自动选中**，顶掉 overhaul 原有的树
9. **`rm -rf` 可能被安全软件静默拦截**，导致 `cp` 拷进旧目录形成嵌套，改动看似没生效
10. **HOI4 有单实例锁** —— 旧进程在跑时新进程直接退出，日志不刷新，会骗你以为改动没生效

## 一句话方法论

> **不要相信「看起来对」**。这个引擎的失效方式大多是静默的：
> 能加载 ≠ 生效，没报错 ≠ 正确。
>
> 每次改动后用三件套验证：
> 1. `error.log` 里 grep 你这次的命名空间前缀
> 2. `game.log` 里找引擎自报的数量（如 `Loaded N provinces`）
> 3. 真进游戏看一眼（日志证明不了渲染和 UI）
